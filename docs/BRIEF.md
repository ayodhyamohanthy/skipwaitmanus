## What SkipWait is
- skipwait.me: a job seeker sends one ask (an official careers-site or ATS job link, a resume and a short note); only employees of that employer who verified their work email can see it, accept it and refer.
- Goal (D-010, D-026): the go-to global site for job referrals, getting people referred faster. Compass: referrals are the product; credits are the revenue engine; quality is the moat; never risk anyone's money.

## How to ship
- Stack: Express, React, TypeScript, Azure MySQL (Drizzle), Tailwind, React Query; Cloudflare Containers and Pages; pnpm 10, Node 22+.
- Branch or worktree per lane; never force-push, rewrite history, `git reset --hard` a shared tree or commit others' files. Failing test first for logic. Zod at every boundary, shared contracts in `shared/`, no `any`. Every query checks the signed-in owner and company scope (MySQL has no row-level security), with a cross-user test. Compute times in the app, never compare MySQL `NOW()` with `Date.now()`. Logs and Sentry carry no tokens, query strings, personal data or single-use links. No new dependency without the owner. Declare env keys in `.env.example`; server secrets need the `src/worker.ts` passthrough.
- Gate, on your commit merged with the latest `origin/main`: `pnpm check`; `node scripts/design-token-audit.mjs`; `bash scripts/lint-deploy-migrations.sh`; `node scripts/check-deploy-triggers.mjs`; `LANG=en_US.UTF-8 pnpm vitest run`; `pnpm build`.
- **Green before `main` (D-082).** Land only when `main`'s latest CI is green (while it is red, push nothing but the fix and tell the owner), the gate passes, and GitHub CI is green on that exact commit: push your branch, open a PR (draft for Tier 1), wait for every check, then fast-forward `main` to that commit (`git push origin <sha>:main` or the merge-commit button; never squash, D-134 (6)). Docs-only PRs: focused checks, an independent delta review and CI, no full re-gate when `main` moves (Oct 23 amendment). Never land on a failing, skipped or running check, weaken a test or use `--no-verify` (GitHub refuses with GH013).
- A push to `main` deploys what it touches (D-003). Watch CI and both deploys to the end; if anything goes red, revert or fix your commit first. Then `EXPECTED_SHA=<sha> bash scripts/verify-live-release.sh` must print CONVERGED (when the API deployed), skipwait.me must serve `<meta name="git-commit">` with your SHA (web), and check affected screens at 1280 and 390. Mark the row done with the SHA.
- Migrations: the next free number on `main` (`drizzle/deploy/`) and in plan §5; never destructive; schema-dependent code lands only after its migration is verified.
- Owner actions: plan §6. System map: `AGENTS.md`.
