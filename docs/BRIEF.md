## What SkipWait is
- skipwait.me: a job seeker sends one ask (an official careers-site or ATS job link, a resume, a short note); only that employer's work-email-verified employees can see, accept and refer.
- Goal (D-010, D-026): the go-to global site for job referrals, getting people referred faster. Compass: referrals are the product; credits are the revenue engine; quality is the moat; never risk anyone's money.

Reuse the picker’s session-tagged name for every flag; never another's. Every pick opens with the newest decisions: a newer one beats your packet — `--report blocked` naming it. Work a newer decision names is withheld as `re-sync (D-nnn)` until any session re-syncs its packet (D-202). Order, top down over `docs/plans/assignments.json`: red `main`; your own unfinished work (unowned pending work above it first); pending work nobody is on; new work. A red or blocked task holds its lane and dependents, a task waits while a dependency is not done, and red `main` holds everything (D-109, D-134). A claim with no push or `--heartbeat` for 2 hours is free. `--report` to the CEO when you stop, land, open a PR or get blocked; `--status` is the shared board. Details: `docs/DELEGATION.md` §4a.
- Implement only from your packet in `docs/plans/` (D-074) and edit only the paths it names. Tier 1 (money, sign-in, identity, privacy, migrations) gets a review on a draft PR before `main` by a model that neither built nor fixed it (D-151). ## How to ship
- Stack: Express, React, TypeScript, Azure MySQL (Drizzle), Tailwind, React Query; Cloudflare Containers and Pages; pnpm 10, Node 22+.
- Branch or worktree per lane; never force-push, rewrite history, `git reset --hard` a shared tree or commit others' files. Failing test first for logic. Zod at every boundary, shared contracts in `shared/`, no `any`. Every query checks the signed-in owner and company scope (MySQL has no RLS), with a cross-user test. Compute times in the app, never compare MySQL `NOW()` with `Date.now()`. Logs and Sentry carry no tokens, query strings, personal data or single-use links. No new dependency without the owner. Declare env keys in `.env.example`; server secrets need the `src/worker.ts` passthrough.
- Gate, on your commit merged with latest `origin/main`: `pnpm check`; `node scripts/design-token-audit.mjs`; `bash scripts/lint-deploy-migrations.sh`; `node scripts/check-deploy-triggers.mjs`; `LANG=en_US.UTF-8 pnpm vitest run`; `pnpm build`.
- **Green before `main` (D-082).** Land only when `main`'s CI is green (while red, push nothing but the fix and tell the owner), the gate passes and GitHub CI is green on that exact commit: push your branch, open a PR (draft for Tier 1), wait for every check, then fast-forward `main` to it (`git push origin <sha>:main` or the merge-commit button; never squash, D-134 (6)). Docs-only PRs: focused checks, an independent delta review and CI; no full re-gate when `main` moves (Oct 23 amendment). Never land on a failing, skipped or running check, weaken a test or use `--no-verify` (GitHub refuses with GH013).
- A push to `main` deploys what it touches (D-003). Watch CI and both deploys to the end; if anything goes red, revert or fix first. Then `EXPECTED_SHA=<sha> bash scripts/verify-live-release.sh` must print CONVERGED (when the API deployed), skipwait.me must serve `<meta name="git-commit">` with your SHA (web); check affected screens at 1280 and 390. Mark the row done with the SHA.
- Migrations: the next free number on `main` (`drizzle/deploy/`) and in plan §5; never destructive; schema-dependent code lands only after its migration is verified.
- Owner actions: plan §6. System map: `AGENTS.md`.
