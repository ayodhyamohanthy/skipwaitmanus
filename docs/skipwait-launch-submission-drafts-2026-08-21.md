# SkipWait.me: Public Launch Submission Drafts

## Submission stop condition

The source application’s public launch copy is ready, but **do not submit it yet**. The canonical hostname `https://skipwait.me` currently resolves to a different Caddy-hosted application, rather than the verified SkipWait source deployment. A direct browser check showed an unrelated “Skipwait Beta” page; after its loading state, it routed to a generic social-sign-in account form at `/login?next=/inbox`, not the verified blue/slate SkipWait landing experience. Sending launch-platform visitors to that hostname now could misrepresent the product and create a poor or unsafe first experience.

> Submit only after the launch URL visibly serves the verified SkipWait landing page, HTTPS is valid, and the primary Job Seeker and Referrer entries complete their intended public handoff. This is a public-launch prerequisite, not a reason to make an unverified VibecodeApp cutover.

The current verified source deployment remains the application reference; do not substitute a preview URL or claim VibecodeApp hosting before its staging parity and cutover gates pass.
