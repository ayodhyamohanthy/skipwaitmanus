## P0-ask-link-signin: a personal-link ask keeps its referrer across sign-in (lane `ask-signin`)
**Why.** A referrer's personal link (D-017) runs `/fast/:code` → `/start?fast=…` (`client/src/pages/FastTrackLink.tsx:26`) → `/request?fast=…` (`client/src/pages/Onboarding.tsx:55`) → `/ask?fast=…` (`askRedirectTarget`, `client/src/lib/fastTrackHandoff.ts`). Neither `/start` nor `/ask` asks a visitor to sign in first. Since #431 (`d3da2497`), a signed-out seeker who presses Send is sent to `goToSeekerSignIn("/ask")` (`client/src/pages/explore/useAskComposer.tsx`, the `!isSignedIn` branch of `send`). The `fast`, `referCompany`/`referAlias` and `post` parameters live only in `window.location.search`, `saveAskPrefill` keeps only the company, link and note, and it saves nothing when the link matches no directory company. After sign-in, `fastTrackAskFields(window.location.search)` is empty, so the ask goes to **every** available verified employee instead of the link's owner, and a posted role's first look (D-022, `opportunityId`) is lost. The page also promises "We keep your link and reasons." The kit page (`d3da2497^1:client/src/pages/Ask.tsx:206`) used `SignInButton`, whose return path kept the full URL with its query (`client/src/_core/auth.tsx:80-83`).
**What.**
1. **Red first** (`client/src/pages/ask.test.tsx` or a new `client/src/pages/askSignIn.test.tsx`): a signed-out send from `?fast=abc` signs in with the return path `/ask?fast=abc`; the same for `?referCompany=tcs&referAlias=asha` and for `?post=12`. Back on that path signed in, the POST body carries `fastTrackCode`, or `fastTrackCompanySlug` with `fastTrackAlias`, and `opportunityId`. A link that matches no directory company still has its link and reasons back after sign-in.
2. **Fix.** Keep the referral parameters across sign-in: the return path is `/ask` plus only the known keys (`fast`, `referCompany`, `referAlias`, `post`) from the current search, nothing else. Save the prefill whenever there is a link or a reason, not only when a company resolved (extend `client/src/lib/askPrefill.ts` minimally if it needs a company).
3. The explore drawer and the company door share `useAskComposer`; keep their own return paths unchanged and pin that.

Owned paths: `client/src/pages/explore/useAskComposer.tsx` (the sign-in branch of `send` and the sign-in prefill restoration effect only), `client/src/pages/explore/signInHandoff.ts`, `client/src/lib/askPrefill.ts` (only if needed) and their tests. Done: red-first tests, full gate, independent review passed, landed, and a live check on the preview or production: signed out, open a personal link, send, sign in, and confirm in the network panel that the ask carries the link.
