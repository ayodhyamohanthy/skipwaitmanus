## 0. What this row builds (D-264 (1))
D-094 wave 1 has three items and this one existing row builds all three, in three steps: **item 2** (job-link auto-fill) and **item 3** (catalogue status help) need no model, provider, env key, migration or spend; **item 1** (the reasons coach) is built in code **behind an in-code switch that starts `false`**, with today's help line as its fallback, and **no provider, account, env key, setting or money change**. Turning the coach on is not part of this row: it needs the D-204 (3) provider (Azure OpenAI on startup credits first, Bedrock fallback) with confirmed data terms (D-139), the owner's lifting of the Oct 31 restrictions (`docs/BUILD_CONTINUITY.md`: "no production changes, migrations, drills, settings changes or spending") and the §13 owner question. This packet adds no row, and nothing in it releases the row for building: the hold stays until the coordinator qualifies it and the gates in §12 clear.

## 1. Goal
Three suggestions, each honest about what it is, with the seeker in control. A seeker writing their three reasons can press "Sharpen this" and get up to three questions about what they wrote, never a sentence written for them (live only once the owner turns it on). A seeker who pastes a job link into the ask drawer (`/explore/<company>`) or `/ask` sees, before sending, which company and which role the link is for, or one plain line saying the link could not be read and that they can still send it. A seeker in My asks (`/requests`) can open "What this means" on any ask and read, in plain words from an approved catalogue, what its status means and what happens next. The job-link line and the status help use no model, and in the shipped state (coach switch `false`) nothing is generated by a model. A coach turned on later would generate questions with a model; that is gated separately (§12) and is not shipped behaviour of this row. Nothing changes what the server sends, spends or resolves.

## 3. Current behaviour (verified on `05d0f7de`)
1. **A job-link preview already exists, server side.** `previewJobLink` (`server/jobLinkPreview.ts:26`) normalizes the URL, fetches direct-employer and public Greenhouse pages through the safe fetcher `fetchPublicJobLink` (`:25`, pinned public DNS, 8 redirects, 5 s, 512 kB), resolves the employer and returns `JobLinkPreview` (`:10`): `canonicalUrl`, `status` (`fresh`/`unreachable`), `employerConfidence` (`verified`/`direct-domain`/`ambiguous`/`unreachable`), optional `companyDomain`, `companyName`, a `reason` and a `recoveryAction` sentence. It caches results (`BoundedTtlCache`, 120 s fresh, 15 s otherwise). **It reads the fetched body only for reachability: no role title is extracted.**
2. **The route.** `registerJobLinkPreviewRoutes` (`server/jobLinkPreviewRoutes.ts:5`) serves `POST /api/job-link/preview`, public, 8 kB body, 12 previews per IP per minute (429 with `Retry-After`), 400 for an invalid or unsafe link, `Cache-Control` 120/15 s.
3. **Who calls it.** Only onboarding (`client/src/pages/Onboarding.tsx:44`) and the goal start page (`client/src/pages/goal/start/GoalStart.tsx:55`, debounced, `previewHasSafeEmployer` at `:58`). **The ask composer never calls it.**
4. **The ask composer's link check is local.** `useAskComposer` (`client/src/pages/explore/useAskComposer.tsx`) computes `linkOk` (`:377`) as `isValidTargetRoleUrl(url) && (!company || jobLinkFitsCompany(url, company.domains))`; `missing` (`:422`) blocks sending while it is false. `jobLinkFitsCompany` (`shared/referralUrl.ts:77`) accepts the company's own domains **and every `HOSTED_JOB_PLATFORMS` host** (`:81`; pinned by `server/workEmailDomains.test.ts:20-22`), so any hosted link (Greenhouse, Lever, Workday, Ashby) passes on any company door, including another company's posting. *(Corrected on `f5b9afb9`: the earlier text said hosted links were refused; §15 F1.)* The refusal comes from the server after Send: `createCompanyReferralRequest` throws `CompanyLinkMismatchError` (`server/db.ts:1877-1879`, "This job link is not from <Company>…") when the link's resolved employer is not the door company, before any credit moves (`server/companyReferralSelectedCompany.test.ts`). The preview route resolves with the same function, `resolveEmployerDomainFromTargetUrl` (`server/_core/index.ts:168`, `server/db.ts:1497`). The send body carries `confirmedCompanyDomain` (`:490`, `confirmedDomain(url)`) and the server resolves the employer itself.
5. **`/ask` finds the company the same local way.** `client/src/pages/Ask.tsx:59-60` sets `urlCompany` to the first directory company whose domains `jobLinkFitsCompany` matches, else `null`. Because that check accepts every hosted host (§3.4), a hosted link with no company chosen matches the **first** directory company, and the send carries its slug (`useAskComposer.tsx:488`, `company = slugCompany ?? urlCompany` at `Ask.tsx:53`); the server then refuses the request naming that unrelated company. *(Corrected on `f5b9afb9`; an existing defect on `main`, reproduced in §15 F4.)*
6. **The link field** is labelled "Job link" in `AskDrawer.tsx:145` and `Ask.tsx:142`; neither shows a company or a role from the posting.
7. **My asks shows one next-step line per ask.** `askNextLine` (`client/src/pages/MyRequests.tsx:40`) returns a sentence for `pending`, `approved`, `intro_made`, `declined`, `withdrawn` and `closed` and falls back for the rest of `referralStatuses` (`shared/referral.ts:1`, which also has `interview` and `offer`) to `requestNote` (`client/src/components/requests/requestModel.ts`). `askView` (`client/src/components/requests/askView.ts:14`) gives the status label and stepper. **There is no help that explains what a status means**, and no copy catalogue keyed by status.
8. **Localisation.** There is no runtime string catalogue yet (`docs/plans/global-readiness-i18n-ai-plan.md` §2 is a plan; copy is hardcoded English outside goal-UI `content.json`).
9. **Model plumbing.** `modelRouterConfigured` (`server/_core/modelRouter.ts:21`) is true only when `AI_PROVIDER_BASE_URL`, `AI_PROVIDER_API_KEY` and `AI_MODEL` are all set; `routeChat({ system, user, maxTokens, fallback })` (`:25`) returns `fallback` when it is not configured or the call fails. Skippy's admin cap is `SKIPPIE_DAILY_CAP` (`server/scheduledJobsRoutes.ts:243`); **no seeker-facing per-user or global model cap exists** (D-138 needs both).
10. **The reasons field.** Three reasons of up to `WHY_ME_MAX` (140) characters (`AskDrawer.tsx:3,194-199`); today's help line is "Three reasons, up to 140 characters each. One specific result beats a list of skills." (`AskDrawer.tsx:194`). `/ask` renders the same field.
11. **Auth on seeker routes.** Routes resolve the signed-in account with `deps.resolveIdentity(req)` and answer 401 without one (`server/privateReferralRoutes.ts:743-744`). Route wiring lives in `server/_core/index.ts` (`registerJobLinkPreviewRoutes` at `:168`).

## 4. Target behaviour (rulings D-264; changeable)
1. **Role title from the posting (server).** `previewJobLink` adds an optional `roleTitle` to `JobLinkPreview`, read only from a body it already fetched (§3.1): first a JSON-LD `JobPosting` `title`, else `og:title`, else `<title>`; HTML entities decoded, tags stripped, whitespace collapsed, at most 120 characters, and dropped when empty or when it equals the company name alone. No extra request, no new host, no model. A link whose body was not fetched has no `roleTitle`.
2. **The composer asks for the preview.** `useAskComposer` calls `POST /api/job-link/preview` for a valid link, debounced 450 ms (the `GoalStart.tsx` pattern), at most one request in flight, keyed by the normalized URL, and keeps the last result for that URL. A 429, 400, network error or timeout gives "no preview", never an error banner.
3. **What the seeker sees under "Job link"** (drawer and `/ask`, one shared component), with honest labels:
   - safe employer (`verified` or `direct-domain`) and a role: "From the posting: <roleTitle> at <Company>";
   - safe employer, no role: "From the posting: a role at <Company>";
   - `ambiguous` or `unreachable`, or no preview: the preview's own `reason` sentence, then "You can still send it; we check the company when you send." (the plain failure line; the field stays editable and nothing is blocked by the preview). **Open, §15 F2:** for every non-Greenhouse hosted link the preview's `reason` is "We could not reach this job link." although no fetch was attempted.
   The line is text, never an input the seeker must accept; the seeker stays in control (D-094 "suggestions only").
4. **Careers-site match on a company door.** On `/explore/<company>`, a preview whose safe `companyDomain` is one of the door company's domains counts as a match for `linkOk`, so a hosted posting of that company is no longer refused; a safe `companyDomain` of another company shows "This posting looks like <Other>'s, not <Company>'s." and `linkOk` stays false exactly as today. Without a safe preview, `linkOk` is today's local check, unchanged. **Open, §15 F1:** today `linkOk` is already true for every hosted link, so the first half changes nothing and "stays false" would be a new client-side block.
5. **`/ask` uses the preview to find the company** only when the local match (§3.5) finds none: a safe `companyDomain` that a directory company owns sets `urlCompany`. The local match still wins when both exist. **Open, §15 F4:** for a hosted link the local match always "exists" (the first directory company), so this fallback never runs.
6. **The server stays the authority.** The send body (`buildAskBody`, `client/src/pages/explore/askSend.ts`) is unchanged: no `roleTitle`, no preview field. The server's own employer resolution, the spend and the D-147 credit rules are untouched. These keep item 2 off the money and identity paths; they do not lower the tier, because `Ask.tsx` sits on the Tier 1 floor (§12).
7. **Status help catalogue (client).** A new `client/src/components/requests/statusHelp.ts` exports `STATUS_HELP`, keyed by every value of `referralStatuses`, each entry `{ title, body }` in plain words, plus `statusHelpFor(request)`. Every sentence is retrieved from the catalogue (no generation, no interpolation except the company name). The catalogue says what the status means and what happens next; it **never states a credit movement** (refund, charge, credit back) — money lines stay where `requestNote` already proves them (§2, MyRequests contract; D-147). **Open, §15 F3:** the visible states are more than the eight `referralStatuses`.
8. **"What this means" in My asks.** Each ask row in `MyRequests.tsx` gets a small "What this means" disclosure (keyboard reachable, `aria-expanded`) that shows `statusHelpFor(request)`. Closed by default; nothing else on the row moves.
9. **Localised (required by D-094; open, stop and ask).** D-094 (3) says the help is "localised". There is no runtime string catalogue on `main` (§3.8), and this packet does not narrow the requirement. **Proposal, pending acceptance:** key `STATUS_HELP` by status so the i18n foundation (`global-readiness-i18n-ai-plan.md` §2) can carry it per locale; whether English-only at first satisfies "localised" is not decided here. Step 2 does not land until the coordinator recovers the delegated scope or accepts a ruling.
10. **The approved microcopy catalogue (required by D-094; open, stop and ask).** D-094 (3) says retrieval from "the approved microcopy catalogue" with no generation. No approved catalogue was found on `main`; wording already on `main` (`askNextLine`, `requestNote`, `askView` labels, `shared/conversationCopy.ts`) is **not** that catalogue. **Proposal, pending acceptance:** the builder drafts candidate entries from that wording, each with its source, for approval; they count as approved only once accepted by whoever D-094 delegates it to. Step 2 does not land until then.

**Item 1, the reasons coach (built off).**
11. **The switch.** `shared/reasonsCoach.ts` exports `REASONS_COACH_ENABLED = false` (in code, D-042: an off-switch never depends on a vendor). While it is `false` the client shows no coach control and the server route answers 404, exactly like a route that does not exist. Nothing in this row sets it to `true`.
12. **The route.** `POST /api/ask/reasons-coach` (`server/reasonsCoachRoutes.ts`, wired in `server/_core/index.ts`, switch-only lines): signed-in seekers only (`resolveIdentity`, else 401); body `{ reasons: string[3] }` each at most `WHY_ME_MAX`, plus an optional `roleTitle` (at most 120) and `companyName`, 4 kB limit. **Nothing else is sent to the provider: never the resume, name, email, job link or any id** (D-139).
13. **Caps (D-138), and why they are not a hard stop.** The code holds a per-user and a global daily cap, counted before the model call (defaults `REASONS_COACH_USER_DAILY = 5`, `REASONS_COACH_GLOBAL_DAILY = 200`, code constants, no env key); over a cap: 429 with "You've used today's coaching. Your reasons are fine to send as they are." **Limit, stated plainly:** these counters live in process memory, so every restart and every extra process or replica starts a fresh allowance; real use can exceed both caps. They do **not** satisfy the D-138 / D-204 hard stop. Turning the coach on stays blocked until a budget guard is proven (for example a shared, durable counter plus a provider-side hard budget), which needs a migration or a provider setting, both outside this row and inside the owner's holds.
14. **The model call.** Only when the switch is on **and** `modelRouterConfigured()` is true: one `routeChat` with a fixed system prompt that asks for at most three short questions about the seeker's own words and forbids writing facts, numbers, employers, titles or achievements. Otherwise no questions, and the client shows today's help line (§3.10). **Limit:** `routeChat` falls through to the legacy Manus Forge path (`server/_core/modelRouter.ts`, after the configured-provider block) when the configured provider errors or returns nothing, so a configured router does not prove D-204 (3) is the sole provider. That is a second enablement blocker; this row does not edit the router (§5).
15. **Output guard (no invented facts).** The server keeps a line only if it ends with "?", is at most 160 characters and introduces no digit, percentage, currency amount or proper noun that is not already in the seeker's reasons, role title or company name; it returns at most three kept questions, or none. The coach never edits the reasons field.
16. **The control.** Under the reasons, a "Sharpen this" button (only when the switch is on and the seeker is signed in); its result is a list of questions labelled exactly "Coach suggests - your words, your facts", dismissible, never inserted into a field. Zero questions or any error shows today's help line. Credits-only cost guard: the coach costs the seeker nothing and never touches credits or cash (D-094). With the switch `false` nothing model-generated is produced, sent or shown, so the shipped off path needs no model-output qualification; any path that produces model output is qualified separately before enablement.

## 8. Edge cases
- The seeker edits the link while a preview is in flight: a result for an older URL is dropped (keyed by normalized URL).
- Offline: no request; the plain failure line is not shown while offline (the composer's offline line already says it).
- A preview arrives after the seeker pressed Send: the send uses today's checks; the preview never retracts a send.
- A title with script or markup: stripped to text by `extractRoleTitle`; React renders it as text (no `dangerouslySetInnerHTML`).
- Rate limit: 12 previews per IP per minute is unchanged; the debounce keeps a typing seeker well under it.
