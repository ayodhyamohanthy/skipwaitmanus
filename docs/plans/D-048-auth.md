## 1. Goal

Two auth surfaces get a goal-doctrine version that lands **dark** (no production change), while the founder-locked login rule keeps exactly one code path.

- `D-048-p3-verify` — `/verify`, the work-email code step a referrer must pass to review asks (D-030). Today it is a kit page inside the app shell: kit heading, kit progress bar, kit card and kit side panel, kit buttons. A referrer should open on their goal ("Refer someone at {company}." in the doctrine's words), see one next step per stage, and get the same honest server facts: which domains the directory proves, how many tries are left, when a resend is allowed, and what a verified badge really shows.
- `D-048-p3-signin` — `/forgot-password` and `/reset-password`, the two seeker password pages, in the goal design next to the goal sign-in that already landed dark (`client/src/pages/GoalSignIn.tsx`, #404), plus `/reviewer-sign-in`, the founder-approved demo sign-in for payment and press review, which D-167 folded into this row (`docs/plans/GOAL_UI_COVERAGE.md:227`). The goal sign-in itself is **not rebuilt by this lane** (§4 rule 8).

Nothing here changes who may sign in, what a code proves, what a reset does to sessions, or any price. Those are decided (D-030, D-049, D-057, D-078, D-080) and are re-stated below as binding.

## 8. Edge cases and races

- Auth loading is a third state, never "signed out": `Verify.tsx:134-141` shows a loading frame while `isLoaded` is false; the goal page must not offer a code send under an unknown identity.
- Receipt reuse: the single-use receipt stays in memory only (`Verify.tsx:42`); a remount loses it and a new code is required — the goal page must not persist it in `localStorage`, a query string, a URL or a draft.
- In-flight double submits: `sending` (`:67`) and `verifying` (`:106`) guard the buttons; the resend countdown and the attempt counter never trust the client's clock for correctness (only the server's refusal does), and no timestamp comparison mixes MySQL `NOW()` with `Date.now()` (AGENTS.md invariant 5).
- Directory failure must not block the email step's validation copy: the primary domain falls back to `company.com` in the placeholder only (`Verify.tsx:186`); a goal page never invents a company name.
- Forgot-password: a 429 and a network failure keep the typed email and the "Check your email" state distinct; the neutral `{ok:true}` answer is shown even when the account does not exist (server `:124-136`) — that is the enumeration guard, not a bug.
- Reset: an absent token, an invalid token, a valid token whose confirm then returns `expired`, and a confirm that succeeds but whose follow-up sign-in fails are four different panels; none may claim a session the server did not grant (§4 rule 7). The token is read once (`ResetPassword.tsx:6-9`) and never re-serialised into a link.
- Reviewer: the route 404s unless `REVIEWER_LOGIN_ENABLED=true` (§3 rule 13), so `/reviewer-sign-in` must render its form and fail honestly rather than crash or claim a live review account; the limiter is per-IP *and* per-email (`server/_core/reviewerLogin.ts:71,78`), so a 429 keeps the typed email but never the password in a rendered error, draft or log; `/admin` is a landing only where `REVIEWER_ALLOW_ADMIN=true` (`:80`), so the page offers no role switch; a session from a demo account is an ordinary session (`:86-89`), so the goal copy must not call it a preview or read-only mode.
- Offline: suppress actions needing the server, keep the entered email or code, and say so with `NETWORK_MESSAGE` (`verifyApi.ts:10`) rather than a raw fetch error.
- Goal-vs-kit import rule: a goal file importing `components/kit/**` or `styles/kit.css` fails the boundary check (`client/src/test/goalPagesBoundary.test.ts` once F-goal-check lands, `client/src/components/goal/goalBoundary.test.ts` today); a kit file importing goal fails the check that exists now. Neither is fixed by editing a test.
- Mobile: 44px targets, the six code boxes stay in one row without wrapping at 390px, and no horizontal overflow at 1280 or 390 (`capture.mjs` reports `horizontalOverflowPx`).
