## Why
The owner, Oct 23: "the online repo and offline should always be in sync and once branches are done and merged to main those should be deleted online and offline". On `ecdbc227`, origin has 345 branches besides `main`. The tips of 69 are already in `main`. The other 276 mix real unmerged work with squash-merged PRs (a squash merge leaves the branch tip outside `main`) and with the picker's marker branches: 11 review locks, 7 heartbeats, 3 architect claims, plus 7 dependabot branches. Nothing deletes a branch after it lands. The picker already prunes remote-tracking refs (`scripts/next-task.mjs:207`, `git fetch -q --prune origin`) but never local branches.

## Rulings (D-205)
1. **Done and merged** means either the branch tip is an ancestor of `origin/main`, or a merged pull request's head SHA equals the branch tip (merge button or squash). Only such branches are deleted. A branch with any commit outside that, or with an open pull request, is never deleted by a script; it is listed for the CEO's triage.
2. **Never deleted:** `main`, `agent/reports/log` (the team's report log), the landing slot `agent/queue/landing` (`scripts/nextTaskCore.mjs:30`), and any branch of a task whose status is not `done` (its task branch, its review lock `agent/review/<slug>`, its heartbeat `agent/heartbeat/<slug>`), and the fix-main lock of a red `main`.
3. **Marker branches** go when the stage they mark is over. An architect claim `agent/architect/<slug>` goes once its row is no longer `architect`. A review lock and a heartbeat go once their task is `done`. Their tips are not in `main`, so for them rule 1 is replaced by this check. The review record stays on the pull request, where reviews are posted (`docs/DELEGATION.md` §6).
4. **Online, going forward:** the owner turns on GitHub's "Automatically delete head branches" (Settings, General; free), so a merged pull request's branch goes at once. The picker's printed landing step also deletes the task branch and its marker branches after the live check.
5. **Offline:** on every run, the picker deletes local branches whose upstream is gone and whose tip is in `origin/main`, using safe delete (`git branch -d`, never `-D`). It never touches the checked-out branch, a branch checked out in another worktree, or a dirty worktree. Anything else it reports as a note.

## SYNC-clone-guard: one command keeps any clone and GitHub in sync (lane `repo-hygiene`, Tier 2, D-373 (5))
**Why.** The owner, Nov 21: "make sure things are pushed to main automatically once things are green over syncing through GitHub desktop . Offline and online should be sync". `scripts/sync-check.sh` (zsh, Mac only) still prints `git add -A && git commit -m 'sync' && git push`, `git push origin main` and `git pull --rebase origin main`. The first commits other sessions' files, and the other two are refused by the D-082 ruleset or rewrite local history. Work committed in a local clone but never pushed is invisible to the picker and to every other session until someone pushes it by hand.

**Build** `scripts/sync-clone.mjs` (Node, any OS; git I/O) with its pure rules in `scripts/syncCloneCore.mjs` and tests in `scripts/syncClone.test.ts`. `scripts/sync-check.sh` becomes a wrapper that runs it. There is no `package.json` script line: that file is in the web deploy's path filter, so the line would start a no-op production deploy.
1. `git fetch --prune origin`.
2. **Online to offline.** Fast-forward the local `main` to `origin/main`, but only when the local `main` has no commit of its own: `git merge --ff-only` in the worktree that has `main` checked out when that worktree is clean, otherwise a compare-and-swap `git update-ref` when no worktree has it. Never rebase, reset or merge into `main`. A local `main` with its own commits is reported: that work belongs on a branch and a pull request.
3. **Offline to online.** For every local branch, across all worktrees, with commits its `origin` branch of the same name does not have, push it to that same name (`git push origin <branch>`). Never `main`, `agent/reports/log` or the landing slot, never `--force`, never another name, and never a branch named `local/*`, `private/*` or `wip/*` (kept local on purpose). A branch whose origin branch was deleted (its pull request merged) is reported, not re-published. A branch whose new commits add a sensitive file name (`.env*` other than `.env.example`, keys, credential files) or a likely key (private key, AWS, GitHub, Slack, Stripe live, Google) is reported, not pushed, without repeating the match (D-059). A refused push (the remote moved) is reported and not retried. Git prompts are off, so a background run fails and reports instead of waiting for a password. Pushing committed work to its own branch is what every session is told to do after each commit (AGENTS.md rule 6), so this only finishes a step a session skipped.
4. **Clean up.** Run `node scripts/branch-cleanup.mjs --local` (BRANCH-HYGIENE-1): safe delete (`git branch -d`) of branches that are done and merged, never the checked-out branch, another worktree's branch or a dirty worktree. Then `git worktree prune` for worktrees whose folder is gone.
5. **Report.** For each worktree with uncommitted changes: its path, branch and file count. Never commit, stash, reset or delete them; they may be a live session's work. End with `in sync` when nothing is left.
- `--dry-run` prints every step without pushing, fast-forwarding or deleting. Exit 0 when in sync, 1 when something is left (dirty work, refused pushes, a local `main` with its own commits).
- **Automatic.** `--install-timer` (opt-in) writes a user LaunchAgent on macOS that runs the sync every 15 minutes with timestamps, logging to `~/Library/Logs/skipwait-sync-clone.log`; `--uninstall-timer` removes it. Elsewhere it prints a cron line to add. Nothing is installed without the flag. `--no-publish-new` reports never-pushed branches instead of publishing them.

**Red-first tests** (temporary repositories with a bare origin, no network): a committed unpushed branch is pushed to its own name; `main` is never pushed; no push uses force; a refused push is reported, not retried; `main` fast-forwards only when it has no commit of its own; a dirty worktree is reported and left byte-identical; a merged branch is deleted with `-d` and an unmerged one is kept; `--dry-run` changes nothing.

**Owned paths.** `scripts/sync-clone.mjs`, `scripts/syncCloneCore.mjs`, `scripts/syncClone.test.ts`, `scripts/sync-check.sh`, this section and its Status line, and the `AGENTS.md` commands block (one line). Done means red-first tests, green required CI (D-370), landed, and one real run in a clone with its output pasted in the pull request.

## SYNC-auto-push: local work reaches GitHub without anyone pushing it (lane `repo-hygiene`, Tier 2, D-375)
**Why.** The owner, Nov 21: "Make sure local build is pushing to repo without manually pushing to GitHub". SYNC-clone-guard pushes committed branch work only when it runs. Its timer is opt-in (`--install-timer`, typed once per Mac), so a clone where nobody typed it keeps its commits on the machine. Where the timer is installed, a commit can still wait up to 15 minutes. A commit on local `main` is only reported (D-082 never lets `main` be pushed), so it never leaves the machine.

**Build** (on `scripts/sync-clone.mjs`, pure rules in `scripts/syncCloneCore.mjs`, install code in the new `scripts/syncCloneSetup.mjs` so no file passes 300 lines):
1. **Every commit pushes itself.** `--install-hook` writes a post-commit hook into the clone's shared hooks folder, so every worktree has it. The hook runs `sync-clone.mjs --current` in the background, so a commit never waits on the network. `--current` pushes only the checked-out branch, by the same rules as a full run: never `main`, never force, never `local/*`, `private/*` or `wip/*`, never a likely secret, never a branch whose origin branch was deleted after its merge, and a branch whose origin moved is reported, not pushed. The hook skips commits a rebase or a multi-commit cherry-pick replays, and `SKIPWAIT_AUTO_SYNC=off` turns it off for one commit. Its log is `<git dir>/skipwait-sync-clone.log`. The hook never replaces another tool's hook and never writes into a `core.hooksPath` folder: it reports instead. `--uninstall-hook` removes only its own hook.
2. **Local `main`'s own commits are saved, never pushed to `main`.** When local `main` has commits that `origin/main` lacks, the hook (on a commit to `main`) and the full sync push them to `sync/main-<first 8 of the oldest such commit>`. Later commits on the same `main` move the same branch forward. The run says the commits are saved and that a session must bring them in through a queue row and a pull request (D-166); `main` itself is never pushed.
3. **Installed by itself.** `--auto-setup` installs the hook when it is missing and, on macOS, the 15-minute timer when no timer is installed. The picker runs it on every `--claim`. It is silent once everything is in place. It never runs in CI, a test run (`VITEST`) or a Claude Code cloud container (`CLAUDE_CODE_REMOTE`), never re-points a timer that already exists, and never runs after `git config skipwait.autoSync false` or with `SKIPWAIT_AUTO_SYNC=off`. A failure is one printed line and never stops the picker. `--install-timer` now turns on both the hook and the timer, and `--uninstall-timer` turns both off.
4. **One run at a time.** A lock file in the git folder serialises the hook and the timer. A lock older than 10 minutes is treated as stale.

**Unchanged.** A pushed task branch still lands only through its pull request on green required CI, through D-371's auto-land. Nothing here opens, readies or merges a pull request, and nothing commits, stashes or pushes uncommitted work.

**Red-first tests** (`scripts/syncClone.test.ts`, throwaway repositories with a bare origin, no network): the hook pushes each commit on a branch, and the first push sets the upstream; commits on `main` go to `sync/main-<sha>` and origin's `main` never moves; the hook skips a rebase in progress, honours `SKIPWAIT_AUTO_SYNC=off`, and never pushes a private branch or a likely secret; `--current` pushes only the checked-out branch, never forces over a moved origin and does not re-publish a merged branch; another tool's hook is never replaced; `--auto-setup` installs once, is silent afterwards, and does nothing in CI, a test run, a cloud container or after an opt-out; the full sync saves local `main`'s own commits and reports them. The pure rules (`sideBranchForMain`, `planHook`, `hookScript` is valid `sh`, `autoSetupAllowed`) have their own tests.

**Owned paths.** `scripts/sync-clone.mjs`, `scripts/syncCloneCore.mjs`, `scripts/syncCloneSetup.mjs`, `scripts/syncClone.test.ts`, `scripts/sync-check.sh` (comment), `scripts/next-task.mjs` (the `--auto-setup` call on `--claim`), this section and its Status line, and the `AGENTS.md` commands block (one line). Done means red-first tests, green required CI (D-370), landed, and a real run in a clone with its output pasted in the pull request.
